# 运行页实时可见性：SSE 流式 + 节点活动全程可见

## 目标
运行中的节点实时展示当前活动（思考摘要、工具调用、命令、心跳），通过 SSE 即时推送，彻底消除"卡住了吗"的疑问。

## A. 后端：Agent 活动采集（src/run-manager.ts）

### 1. Claude 流式 trace（核心修复）
`runClaude` 从 `--print --output-format json` 改为 `--output-format stream-json --verbose`，复用 `runProcess` 现成的 `onStdoutLine` 逐行解析：
- `system/init` → `status`（"Claude Code 会话已建立 · 模型 xxx"）
- assistant content blocks：`thinking` → `reasoning_summary`；`text` → `agent_message`；`tool_use` → `tool_started`（toolName=Bash/Read/Edit…；`input.command` 写入 command 字段，`input.file_path` 写入 content 摘要）
- `user` 的 `tool_result` → `tool_completed`：按 `tool_use_id` 关联（Map 记开始时间/工具名，同 Codex startedTools 模式），含 durationMs、is_error→status、输出预览（≤400 字符，经 redactPublicText）
- `result` 事件 → 最终输出；`subtype: error_*` → `error` 事件
- `parseClaudeResult` 兼容（stream-json 最后一行即 result）

### 2. Codex trace 增强
`file_change` 事件解析 `item.changes` 带上变更文件路径（进 content，截断）。

### 3. 静默心跳
runCodex/runClaude 执行期间每 45 秒无事件时补发一条 `status` trace："执行器仍在运行（已 N 分钟）"，进程结束清除定时器。

### 4. RUN LOG 活性
`persistAgentTrace` 中 `tool_started`/`tool_completed` 同步写入 `run.logs`（沿用 200 行上限），RUN LOG 面板在 Agent 执行期间持续有动静。

## B. 后端：SSE 实时通道

### 5. 进程内事件总线（新文件 src/run-events.ts）
`subscribeRunEvents(runId, listener)` / `notifyRunChanged(runId)`。`saveRun` 内统一触发 notify（appendAgentTrace/appendEvent/状态变更全部覆盖）。API 路由与 run-manager 同进程（Next standalone 单进程，已有 activeProcesses 单例先例）。

### 6. SSE 路由（新文件 src/app/api/runs/[id]/events/route.ts）
- `GET` 返回 `text/event-stream`（no-cache、X-Accel-Buffering: no、`export const dynamic = 'force-dynamic'`、Node runtime）
- 连接建立：发 `retry: 2000` + 初始 `event: state`（run 状态、nodes 状态、attempts 状态）+ `event: trace`（各 attempt 最近 trace，支持 `?sinceSeq=` 增量起始）
- 订阅总线，通知合并去抖（~80ms）后重读 manifest，推送增量：`event: state`（状态字段）与 `event: trace`（按 attempt 维度、seq/索引之后的新事件，含 traceOmittedCount）
- 每 15s 发 `: ping` 心跳注释保活；`request.signal` abort 时清理订阅；run 进入终态发完最终 state 后 `event: done`
- 鉴权：Electron 的 webRequest 头注入对 EventSource 同样生效，中间件无需改动

### 7. 轮询降频
SSE 连接期间，run-workspace 的 `/api/runs` 全量列表轮询从 900ms 降到 4s（仅用于运行列表/其他 run 的元信息刷新）；选中 run 的实时数据全部走 SSE。SSE 断开（EventSource error）自动回退 900ms。

## C. 前端（src/app/run-workspace.tsx + page.tsx）

### 8. EventSource 接入
- 选中 run 处于活动状态（running/preparing/awaiting_approval）时建立 EventSource，state/trace 事件不可变合并进本地 run 状态（trace 上限 300 条对齐服务端）
- 切换 run、run 完成、组件卸载时关闭连接；EventSource 自带断线重连，重连后由初始 state/trace 事件自动对齐

### 9. 节点实时活动摘要（纯 UI 派生）
- 共享函数 `latestActivity(attempt)`：取 trace 末条事件 → `{ icon, label }`（"🔧 Bash · npm test"、"💭 思考中"）
- 左侧节点列表行 running 时显示活动摘要 + 已用时 + "N 秒前"；canvas 节点卡片（page.tsx）同样加一行

### 10. Attempt 详情默认 tab 智能化
attempt running → 默认"执行过程"；已完成 → 默认"结果"（替换现在无条件回 prompt 的重置逻辑）。

### 11. Trace 自动跟随
运行中 trace 容器自动滚到底部；用户上滚（距底 >40px）暂停跟随并显示"回到最新"按钮。
